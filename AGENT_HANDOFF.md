> Этот файл — точка передачи контекста между ИИ-агентами, помогающими владельцу

> в `docs/JOURNAL.md`. Это правило передаётся каждому следующему агенту.

## Что это за проект

**Kelpwave** — локальные ИИ-агенты, работающие прямо на Android-телефоне
владельца через Termux + llama.cpp, полностью офлайн (без облачных API).

Два агента:
- `agents/kelpwave_companion.py` — интерактивный чат-агент с инструментами
  (bash, чтение/запись файлов, веб-поиск, скачивание). Модель Qwen2.5-Coder-7B
  через llama-server на порту 8080. Архитектура: ReAct-цикл
  (THOUGHT → ACTION → ACTION_INPUT → OBSERVATION), парсинг через regex.
- `agents/kelpwave_reflexion.py` — самообучающийся кодер (архитектура Reflexion,
  Shinn et al. 2023): пишет solution.py, запускает, при ошибке генерирует
  «урок» и сохраняет в lessons_learned.json, который подмешивается в промпт
  следующих попыток. Модель Qwen2.5-0.5B.

## Окружение владельца (важно!)

  команды для копипасты, по одной понятной инструкции за раз. Общение на русском.

## Как работать с владельцем

1. Владелец описывает задачу в чате.
2. Агент правит код у себя, тестирует (можно симулировать: модель недоступна
   в песочнице, но логику цикла можно мокать — см. JOURNAL).
3. Запись в репозиторий:
   - **Если владелец дал fine-grained токен** (выдаётся на 7 дней, только repo
     kelpwave, только Contents R/W) — агент коммитит и пушит сам.
     Коммиты подписывать: `user.name "kelpwave-assistant"`.
   - **Если токена нет** — агент отдаёт файлы, владелец пушит руками.
4. Владелец забирает изменения: `cd ~/kelpwave && git pull`, копирует нужный
   скрипт в рабочую папку, если требуется.
5. **Перед завершением сессии:** обнови этот файл + допиши JOURNAL + запушь.

## История проекта (кратко)

- Проект начат с другим ИИ-агентом (история не сохранилась), файлы были
  раскиданы по 4 местам с разными версиями.
- 2026-06-09/10: новый агент (Arena.ai) собрал проект, нашёл актуальные версии.
- v2: починен запуск llama-server (-fa auto, без --mlock, лог в файл,
  ожидание 180с, предполётные проверки).
- v3: починен веб-поиск (html.duckduckgo.com стал отдавать капчу →
  переход на lite.duckduckgo.com POST + fallback Bing с декодом base64-ссылок);
  fetch_page с gzip; новый инструмент download_file.
- v4: Loop Guard — агент зацикливался, повторяя один web_search;
  теперь повторные вызовы блокируются, при втором повторе или исчерпании
  лимита шагов модель принуждается дать финальный ответ.
- v5: URL Guard — модель галлюцинировала несуществующие ссылки
  (404); теперь download_file/fetch_page принимают только URL, реально
  встречавшиеся в наблюдениях или сообщениях пользователя.
- v6: download_file отклоняет HTML-страницы (модель скачивала
  страницы онлайн-генераторов, считая их файлами). Добавлен tools/doctor.py —
  диагностика окружения (идея владельца: prerequisite-проверка как в A1111).
- v7: URL Guard проверяет неизвестные URL HEAD-запросом (угаданные
  ссылки разрешаются); подготовлен переход на Qwen3-4B-Instruct-2507
  (unsloth GGUF Q4_K_M, 2.3 ГБ) — companion автоматически предпочитает её,
  если скачана. 7B Coder остаётся запасной.
- v8 (текущая): найден корень проблемы «не может скачать файл» — fetch_page
  вырезал ссылки вместе с HTML. Теперь отдаёт текст + секцию DIRECT FILE LINKS.
  Диагноз поставил владелец (заметил, что агент «тычется в страницы вслепую»).
- Проект перенесён на GitHub, владелец освоил git push из Termux.

## Известные проблемы и грабли

- **7B-модель слабовата для агентных циклов:** теряется на расплывчатых задачах
  («скачай что-нибудь»), выдумывает URL. Loop Guard смягчает, но не лечит.
  Советуй владельцу формулировать конкретно.
- **/sdcard = FUSE:** git там не работает (dubious ownership), модель грузится
  медленно. Всё рабочее — в `~`, /sdcard только для обмена файлами.
- **DuckDuckGo может закапчить и lite-версию** — тогда сработает fallback Bing.
  Если оба умрут, нужен новый движок (см. tool_web_search).
- **lessons_learned.json был однажды случайно удалён** — некритично
  (пересоздаётся), но запланирован автобэкап (см. следующие шаги).
- Парсинг ACTION_INPUT хрупкий: модель иногда добавляет markdown-обёртки.
